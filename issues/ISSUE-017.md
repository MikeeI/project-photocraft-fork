## Root-Cause

[S] The UI marks a revision autosaved when the service merely queues its snapshot, before the worker writes it.
Review mapping: `E4`, VALID; severity High.

## Reach-and-Impact

Trigger: A dirty document reaches the autosave interval while recovery storage is unavailable.
- [S] Worker failure leaves the queue acknowledgment intact, excluding an unchanged revision from retry.
[O] A clean-baseline reproduction at `a96a621` observed revision 2 acknowledged before its worker completed.

## Evidence

- [S] At base, native services return queue success before the worker writes the bundle and sidecar.
- [S] The UI records queue success in `prefs_rt.autosaved` and does not consume the worker result.
- [S] `Session::add_document` remaps IDs only among open documents; a lone ID can be reused after reopen.
- [O] Baseline `cargo test --locked -p photocraft-ui-egui --lib prefs_ui::tests::queue_acceptance_is_not_persisted_completion -- --exact` failed because revision 2 was acknowledged before completion.
- [O] The fixed UI tests verify failed-save visibility/retry and reject a late completion after same-ID reopen.
- [O] The format test forces a bundle-write error, observes failure, retries that revision, and recovers the document.

## Proposed-Change

Return revision-tagged worker results to the UI and acknowledge persistence only after success.
Keep failed revisions retryable, surface errors, and bind results and saver lifetimes to each open document incarnation.

## Scope-and-Constraints

- Preserve background saving and snapshot coalescing without blocking the UI on filesystem work.
- Distinguish queued, in-flight, completed, and superseded revisions.
- Do not apply stale completions to closed or unrelated documents.

## API-and-Compatibility

Public `AutosaveFn` includes `document_instance_id`; `Services` requires result polling and fallible discard.
`DocState` adds a public runtime-only `instance_id` generated by `DocState::new`.
These changes require external callback and struct-literal updates; all in-repo callers are migrated.
The instance token is not persisted and does not change the document format.
